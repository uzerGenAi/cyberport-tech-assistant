Prerequisites — tools & credentials

Run once on a fresh machine. Skip anything already installed.

Before you start — verify these
  • AWS CLI configured: aws configure with region eu-central-1
  • Docker daemon running: docker info
  • Terraform ≥ 1.6: terraform version
  • kubectl: kubectl version --client
  • Python 3.10+: python3 --version
  • git, zip, jq, curl available in PATH
# Install dev tools (Docker, kubectl, eksctl) on EC2 / Cloud9
# Only needed on AWS Cloud9 or a fresh EC2 instance bash 6_deploy/scripts/setup_dev_tools.sh
# Install Python agent dependencies
pip3 install -r requirements.txt # Runtime deps + bedrock-agentcore-starter-toolkit (needed by configure_runtime.py) pip3 install -r 6_deploy/agents/requirements-deploy.txt
# Verify AWS identity
aws sts get-caller-identity
# Verify Nova Pro answers in eu-central-1 (via the EU inference profile)
# amazon.nova-pro-v1:0 is listed in eu-central-1 but can't be invoked on-demand there aws bedrock-runtime converse \ --region eu-central-1 \ --model-id eu.amazon.nova-pro-v1:0 \ --messages '[{"role":"user","content":[{"text":"Reply with OK"}]}]' \ --query 'output.message.content[0].text' \ --output text # Must return a short reply (e.g. OK)

Discover & export environment variables

Writes ~/environment/env.sh with your account ID, region, model ARN, and all discovered SPBC resource IDs.

# From the repo root
cd /path/to/Harness_project # your repo root source setup_env.sh
# Load env in every new terminal session
source ~/environment/env.sh
# Verify key variables are set
bash check_env.sh
2
Terraform backend setup run once

Creates the S3 state bucket, DynamoDB lock table, auto-detects your outbound IP, and writes terraform.tfvars with a locked-down eks_public_access_cidrs.

# Standard — auto-detects your current IP
make backend-setup
# With an extra CI/CD runner IP (optional)
bash 6_deploy/scripts/terraform_backend_setup.sh \ --extra-cidr YOUR_CI_RUNNER_IP/32
⚠ terraform.tfvars is gitignored — it contains your IP. Never commit it. Re-run this step if your IP changes.
# Confirm terraform.tfvars was written
cat 6_deploy/infra/terraform/terraform.tfvars # Must contain: eks_public_access_cidrs = ["YOUR.IP/32"]

✅ Expected output: "CI checks passed"
4
Knowledge base setup — OpenSearch + S3

Upload seed data to S3 and create the 4 OpenSearch Serverless vector indexes. Run once before provision so the indexes exist when the agents first query them.

ℹ These scripts require AOSSENDPOINT and WORKSHOP_S3_BUCKET to be set. If they weren't discovered in Step 1, create the OpenSearch collection manually first, then re-run setup_env.sh.
# Upload all seed data to S3
aws s3 cp 2_data_strategy/menu/menu_records.json \ s3://$WORKSHOP_S3_BUCKET/menu/menu_records.json aws s3 cp 2_data_strategy/menu/menu_items_kb_faqs.txt \ s3://$WORKSHOP_S3_BUCKET/bakery_menu/menu_items_kb_faqs.txt aws s3 cp 2_data_strategy/orders/orders_policies_kb_faqs.txt \ s3://$WORKSHOP_S3_BUCKET/bakery_orders/orders_policies_kb_faqs.txt aws s3 cp 2_data_strategy/payments/payments_policies_kb_faqs.txt \ s3://$WORKSHOP_S3_BUCKET/bakery_payments/payments_policies_kb_faqs.txt aws s3 cp 2_data_strategy/stores/store_kb_faqs.txt \ s3://$WORKSHOP_S3_BUCKET/bakery_stores/store_kb_faqs.txt aws s3 cp 2_data_strategy/promos/promos_kb_faqs.txt \ s3://$WORKSHOP_S3_BUCKET/bakery_promos/promos_kb_faqs.txt
# Create the vector store, then every Knowledge Base (equivalent: make knowledge-bases)
bash 3_proof_of_concept/knowledge_bases/bootstrap_vector_store.sh # collection + policies + KB role bash 3_proof_of_concept/knowledge_bases/setup_knowledge_bases.sh # all five domains, each sync verified
ℹ Both scripts are idempotent, so a partial run can simply be repeated. All five domains are covered, including orders — the agent runtime refuses to start without ORDERS_KNOWLEDGE_BASE_ID.
# Re-discover Knowledge Base IDs (written by the setup scripts above)
source setup_env.sh # Confirm these are now set: echo "MENU_KB: $MENU_KNOWLEDGE_BASE_ID" echo "ORDERS_KB: $ORDERS_KNOWLEDGE_BASE_ID" echo "PAYMENTS_KB: $PAYMENTS_KNOWLEDGE_BASE_ID" echo "STORES_KB: $STORES_KNOWLEDGE_BASE_ID" echo "PROMOS_KB: $PROMOS_KNOWLEDGE_BASE_ID"
# Smoke-test the knowledge bases

5
Set up Bedrock Guardrail

Creates the content guardrail and stores its ID in SSM Parameter Store at /SPBC/guardrail/*.

# Create guardrail and write to SSM
bash 5_security_rai/create_and_store_guardrail.sh
# Export guardrail vars for the agent deploy step
export GUARDRAIL_ID=$(aws ssm get-parameter \ --name "/SPBC/guardrail/id" \ --region eu-central-1 \ --query "Parameter.Value" \ --output text) export GUARDRAIL_VERSION=$(aws ssm get-parameter \ --name "/SPBC/guardrail/version" \ --region eu-central-1 \ --query "Parameter.Value" \ --output text) echo "Guardrail: $GUARDRAIL_ID v$GUARDRAIL_VERSION"
6
Provision AWS infrastructure

Runs terraform init + apply. Creates VPC, EKS cluster, ECR, DynamoDB tables, IRSA role, and Cluster Autoscaler. Takes ~15–20 minutes.

# Provision everything
make provision
ℹ This runs terraform apply with -auto-approve using terraform.tfvars. Watch for any errors — if it fails mid-run, re-run make provision (Terraform is idempotent).
# Export the ECR repository URL — required for make deploy
export ECR_REPOSITORY_URL=$(terraform \ -chdir=6_deploy/infra/terraform \ output -raw ecr_repository_url) echo "ECR: $ECR_REPOSITORY_URL"
# Configure kubectl to talk to the new cluster
aws eks update-kubeconfig \ --region eu-central-1 \ --name pastrycafe-prod kubectl get nodes # should show 2 Ready nodes
6b
Provision the AgentCore backends

Separate Terraform stack 6_deploy/infra/agentcore-backends (own state, Terraform 1.10+): Aurora MySQL Serverless v2 stores database read through the RDS Data API, and the IAM-authorized promotions API (spbcBakeryAPI, GET /prod/promotions). Takes ~15 minutes.

# Plan, confirm (type apply), apply exactly that plan
make backends
# Load the stores data + create the read-only user, then smoke-test both backends
make seed-stores make backends-check # reader query, unsigned 403, signed GET /promotions
# Write STORES_DB_* + PROMOS_API_URL into ~/environment/env.sh (read by make post-deploy)
source setup_env.sh echo "$STORES_DB_CLUSTER_ARN $PROMOS_API_URL"
ℹ Aurora Serverless v2 bills per ACU-hour (default 2 instances × 0.5 ACU minimum). For non-production set aurora_instance_count = 1 and aurora_min_acu = 0 in 6_deploy/infra/agentcore-backends/terraform.tfvars.
✅ Expected: "Done: 26 stores readable by stores_reader; writes are denied as expected." and three ✅ lines from make backends-check
7
Deploy the agent backend to EKS

Authenticates Docker to ECR, builds and pushes the Pastry Concierge container, performs a blue/green Kubernetes rollout, and runs the smoke test.

# Authenticate Docker to ECR
aws ecr get-login-password --region eu-central-1 \ | docker login \ --username AWS \ --password-stdin \ $ECR_REPOSITORY_URL
# Build, push, and blue/green deploy
export IMAGE_TAG="$(git rev-parse --short HEAD)" # tag by git commit make deploy
✅ Expected: "Blue/green deployment complete" + "Smoke test passed"
8
Post-deploy — Cognito + AgentCore + Amplify

One command that: creates Cognito pools, launches the AgentCore runtime (waits for READY), writes both config files, then deploys the frontend to Amplify.

# Ensure all KB IDs and guardrail vars are in the environment
source ~/environment/env.sh export GUARDRAIL_ID GUARDRAIL_VERSION # if not already in env.sh
# Run the full post-deploy sequence
make post-deploy
ℹ This takes 5–10 minutes (AgentCore launch polls until READY). It is idempotent — safe to re-run if it fails partway through.
✅ Expected final output: "🟢 System live" with an Amplify HTTPS URL

Day-2 operations ongoing

Common commands after the system is live.

Command When to use
bash 6_deploy/scripts/rollback.sh --status Before rolling back — shows the live colour, the rollback target and ready replicas per colour
make rollback Bad deploy — switches prod traffic back to the previously live colour. Refuses if that colour has no healthy pods.
make amplify UI-only change — re-deploys frontend without touching EKS or AgentCore
make post-deploy Config change (new KB ID, guardrail update) — re-runs Cognito + AgentCore + Amplify
make smoke Periodic health check — set SMOKE_TEST_URL before running
make ci Before any code change — validates Python + Terraform
bash 6_deploy/scripts/terraform_backend_setup.sh --extra-cidr IP/32 New CI/CD runner or office IP — updates EKS API CIDR allowlist (make can't pass the flag through)
make backends-plan / make backends Backend change (e.g. edited promos_records.json — the promotions Lambda is rebuilt)
make seed-stores Reload stores data, or re-sync the read-only user after rotating its secret (idempotent)
make backends-check Health check of the stores database and promotions API, called the way the runtime calls them
make help Print all available targets
