# Deployment Scripts

Deployment assets for the SPBC Pastry Concierge. All of these run without a terminal, so they
can be driven by [.github/workflows/deploy.yml](../../.github/workflows/deploy.yml).

## AgentCore and data backends
- `agentcore_backends.sh`: Terraform stack `6_deploy/infra/agentcore-backends` (stores database through the RDS Data API + IAM-authorized promotions API): `plan`, `apply` (applies exactly the reviewed plan; `AUTO_APPROVE=1` to skip the prompt), `seed`, `check`, `env`, `policy`, `validate`, guarded `destroy`. Run `bash agentcore_backends.sh help`.
- `post_deploy.sh`: Cognito → AgentCore runtime → Amplify. `--force` redeploys even when the config files are populated; `--skip-user` / `--non-interactive` are passed through to the Cognito script.
- `setup_cognito_auth.sh`: User Pool, Identity Pool and IAM role. The sign-in user comes from `COGNITO_ADMIN_USERNAME` plus `COGNITO_ADMIN_PASSWORD_SECRET_ID` or `COGNITO_ADMIN_PASSWORD`; `--skip-user` creates none. It prompts only when a terminal is attached.

## Infrastructure
- `terraform_backend_setup.sh`: Terraform state bucket and lock table, and writes `terraform.tfvars`. The EKS API allowlist comes from `--cidr` / `EKS_PUBLIC_ACCESS_CIDRS`; `0.0.0.0/0` is refused unless `--allow-open`, and failed IP detection is an error rather than a fallback.
- `end_to_end.sh`: `--infra-only` (Terraform apply, non-interactive) and `--deploy-only` (image rollout + smoke test).
- `ci_checks.sh`: local CI (`make ci`): Python compile, Terraform fmt/validate on both stacks, and the mocked `terraform test` suite for the backends.

## EKS rollout
- `build_webapp_image.sh`: builds and pushes the web image on **AWS CodeBuild** (no local Docker), so the deploy pipeline is Docker-free. Resolves `ECR_REPOSITORY_URL` (honoured if exported, else from `terraform output`) and `IMAGE_TAG` (git short SHA, else a UTC timestamp). Ensures the `SPBC-WebAppCodeBuild-Role` service role and the `spbc-webapp-image` project (create-or-update), uploads the `6_deploy/web-app` build context — including the generated `cognito-config.json` / `agentcore-config.json` / `observability-config.json` and the `Dockerfile` — to `spbc-webapp-codebuild-src-<account>-<region>`, starts the build with `ECR_REPOSITORY_URL` + `IMAGE_TAG` overrides, waits, and exits non-zero on failure. Runs immediately before `deploy_blue_green.sh`.
- `deploy_blue_green.sh`: deploys the image to whichever colour is **not** live, waits for it to be healthy, then moves the `spbc-bakery-web-svc` Service to it. A failed rollout leaves production untouched. Requires `ECR_REPOSITORY_URL`; tags must be immutable (`IMAGE_TAG=latest` is refused unless `ALLOW_MUTABLE_TAG=1`). Records the previous colour and image as Service annotations.
- `rollback.sh`: switches the Service back to the recorded previous colour. `--status` reports the current state, `--to blue|green` overrides the target. It refuses to switch to a colour with no ready replicas.
- `smoke_test.sh`: requires `SMOKE_TEST_URL` and checks the response body is this app, so a 200 from a holding page fails. `SMOKE_EXPECT`, `SMOKE_RETRIES` and `SMOKE_TIMEOUT` tune it.

## Frontend
- `amplify-deploy.sh`: creates or reuses the Amplify app and deploys `6_deploy/web-app`.
- `deploy_frontend.sh`, `deploy_stack.sh`: earlier EKS + CloudFront path, kept for reference. Both still contain interactive prompts and are not on any `make` target.

## Notes
The per-colour Deployments are generated by `deploy_blue_green.sh`; `6_deploy/k8s/` holds the
namespace, the Service and the ingress. The ingress still needs a real certificate ARN in place
of `REPLACE_ME_CERT_ARN` before it can be applied.
